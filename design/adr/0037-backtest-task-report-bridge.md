# ADR 0037: Connect backtest valuations to common tasks and reports

Status: accepted

## Context

The common task/report API supports immutable pricing sources and normalized
risk metadata, but the backtest provider still compiled ordinary legacy plans
directly. This left consumers without the actual replayable task and common
report behind a decision. The backtest ledger has narrower financial assumptions
than the general pricing API, and specialized Gamma-chain and paired-sample
operations do not yet have common task equivalents.

## Decision

Translate the existing checked request into a `PricingSpecification` and an
evaluate `PricingTask`. Use its `ValuationReport` for price, uncertainty, ordinary
raw Delta/Gamma and, where requested, the complete native VegaKT payload. Keep the
typed native result for warnings and Gamma bump diagnostics absent from the
normalized risk fields. Perform one ordinary task evaluation per cache miss.

Centralize this boundary in `task_adapter.py`. Check result family, currency,
underlying identity, scalar shape, units, calibration semantics and uncertainty
scope explicitly. Do not infer units or flatten multi-asset/parameter axes.
Retain all request and numerical acceptance checks; a generic task capability
does not authorize a new model, product or risk convention in this ledger.

Expose `RustPricingProvider.pricing_evidence(snapshot, contract)` returning an
immutable `PricingEvidence` after the same acceptance checks as `evaluate`:

- Diagnostic/P0 reports have scope `requested_risks` and retain native VegaKT
  projection/covariance metadata.
- Multi-step reports have scope `ordinary_price_and_greeks`. Market-IV Gamma
  buckets and covariance remain in the separately accepted `gamma_audit`.
- Quote-control returns `None`; its paired-sample report remains authoritative.
  Do not perform another ordinary compile solely to manufacture common evidence.

Evidence records the actual task/report before delayed-payment adjustment, plus
the ledger payment date and scaling factor. It shares the bounded cache entry
with the corresponding risk/audit. Eviction and `clear_cache` release all of
them together; caller-held immutable output remains valid. No compiled state is
retained. This builds on [ADR 0036](0036-backtest-provider-cache.md).

## Impact

- Additive Python companion API; existing `RiskProvider` implementations need no
  new method. Legacy pricing requests remain the ledger input boundary.
- No changes to Rust APIs, serialized ledger/checkpoint schemas, native pricing
  policies, execution settings, seeds, Gamma tolerances or covariance pairing.
- Preserve existing risk provenance formats. Source implementation hashes change
  normally and reject checkpoints from the earlier implementation. Include the
  new adapter in the explicit multi-step implementation identity.
- Native report/task objects add per-entry memory. Existing entry bounds apply;
  they are not byte limits. No runtime speedup is claimed.
- This implements the common source/report architecture of
  [ADR 0030](0030-pricing-task-capability-report.md) at the backtest boundary and
  preserves the existing accepted numerical scopes and roadmap gates.

## Validation

Compare installed-native legacy plan results with common-report-derived ledger
risks, including Gamma method, deferred payment and uncertainty. Round-trip the
actual task JSON and reproduce the report exactly, including full VegaKT bucket
covariance. Verify immutable outputs, no duplicate task evaluation on cache hits,
and equal evidence after eviction/clear.

Reject incompatible currency, underlying axes, units, missing/duplicate scalars,
calibration semantics, uncertainty scopes and unsupported native result families.
Exercise evidence access on failed gates and retain bounded-cache concurrency
tests. Run the accepted multi-step provider/replay tests, compare complete Gamma
audits after eviction, and retain joint covariance and quote-control tests.
Historical numerical acceptance artifacts are not regenerated by this change.
