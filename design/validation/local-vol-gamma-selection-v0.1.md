# 経路依存Gammaの標本分離による正則化選択 — v0.1

2026-10-05。空間平坦・ゼロキャリーのGamma診断に、正則化の選択と独立検証を追加した。
初期Gamma測度と正時刻の回復値を同じ診断で取得できる。式(4)・(9)による
全時刻のIVヘッジとその共分散の数値受入は、この診断の合格とは別に未成立。

## 解決する問題

従来の固定lambdaの72設定では、33節点Asianのlambda=0.01（seed 7/41）と
lambda=0.001（seed 41）の再構成誤差が3%を超えた。
独立参照入力でも約7.28%/3.14%の誤差が残り、標本数やGamma節点数を増やしても
強い正則化の偏りは消えなかった。一方、lambdaを弱めると、商品によっては
Gamma質量の標準誤差が質量ベクトルの大きさに比べて大きくなる。

新しい機能は候補ごとの残差とMC誤差を評価し、条件を満たす最も強い正則化を選ぶ。
過去の固定lambdaを修正・合格へ変更するものではない。
[前回の分析](local-vol-initial-gamma-measure-v0.1.md)と固定lambdaの失敗記録を維持する。

## 選択と検証の分離

元の評価標本数を `N`、選択用標本数を `P` とする。乱数は既存のseed・Valuation領域を使い、

- 検証と初期Gammaはcounter index `[0,N)`。
- 全候補の選択用計算は `[N,N+P)`。候補同士は共通乱数を使う。
- antitheticの正負パスは1ペアとして同じ区間に入れ、ペアの途中で分離しない。

乱数を重複させず、選択用計算だけからlambdaを固定する。
その後に元の評価区間を1回検証する。検証に失敗しても次のlambdaへ切り替えず、
`validation_failed` と選択値・失敗の統計を返す。
候補がなければ `no_feasible_pilot_candidate` とし、回復値をゼロとして返さない。
成功状態 `positive_time_policy_passed` はこの限定的な成分ポリシーの合格のみを表す。

本体に価格公式や独立参照値を渡して選択していない。
候補は実行前に固定し、強い順に厳密降順とする。
request/plan指紋に加え、ポリシー全体と実際の標本区間を出力する。

## 判定式

各時刻で入力局所Vegaを `b`、逆算したGamma質量を `q=Rb`、再構成差を `e=Bq-b` とする。
`||SE_b||` などは各成分の標準誤差を二乗和平方根でまとめたもの。
差 `e` は標本ごとに計算してから統計処理し、`Bq` と `b` の共分散を維持する。

再構成の判定値は

`(||mean(e)|| + m*||SE_e||) / (||mean(b)|| - m*||SE_b||)`

とし、分母が正の場合に限り計算する。Gammaの雑音判定値は

`||SE_q|| / ||mean(q)||`

とする。Gammaの分母が0の場合も識別不十分として不合格。
これらをすべての正時刻で満たす最も強い候補を選ぶ。

`m` は推定誤差に対する余裕であり、同時信頼区間の保証ではない。
各成分の平均・分散・SEを保持するため、外部から判定を再計算できる。
Gammaの正則化バイアス、未観測尾部、連続分布の一意性はこのMC誤差比では保証しない。
`unobserved_source_nodes` と元の寄与数を残し、尾部のSE=0を真のリスク0とは扱わない。

## API

```python
policy = rust_pricing.VegaKtGammaRecoveryPolicy(
    [0.01, 0.003, 0.001, 0.0003, 0.0001],
    pilot_sampling_units=262144,
    reconstruction_relative_limit=0.03,
    gamma_relative_standard_error_limit=0.25,
    mc_margin_multiplier=2.0,
)
audit = plan.evaluate_vega_kt_gamma_recovery_audit(strikes, policy=policy)
```

`pilot_candidates` は全候補の生の診断と判定値、`validation` は選択後の評価標本の診断。
`initial` は同じ評価標本を使う条件付き初期Gamma測度。
`strikes` は正時刻の回復原子位置に使い、初期Gammaでは裾を含む表示区間の境界に使う。
初期Vegaの計算では原子をこの境界へ移動しない。
候補が見つからなくても初期測度を保持する。

既存の固定lambda API・通常価格・P0ガードは維持する。
新機能はpseudo-MC専用で、非平坦分散、キャリー・配当、バリア、早期行使、
平滑化・指示関数、条件付きペイオフが区分線形にならない商品を受け付けない。

## 独立数値検証

[固定した数値ポリシー](../../fixtures/backtesting/gamma-selection-policy-v0.1.json)は、
4商品（call/Asian/既知fixing付きAsian/Lookback）×3格子（9/17/33）×4 seed
（7/41/101/509）の48設定を対象とする。数値参照は2観測の商品で計算する。
選択用262,144ペア、検証用524,288ペア。新しいseedも含め、3%の基準は維持する。
25%のGamma標準誤差比と2倍のMC余裕は追加の判定条件である。

[検証スクリプト](../../scripts/check_gamma_selection.py)は直接積分とNumPy SVDで
各候補・検証の逆算、再構成差、雑音増幅を照合する。公開した統計から選択判定を
独立に再計算し、最大の適格lambdaが選ばれていることを確認する。
独立参照値からのGammaと入力局所Vegaを検証標本のSEで比較し、さらに
参照入力でも選択された作用素の再構成誤差が3%以内であることを確認する。
初期ADの接続と、初期GammaによるVegaとADとの差も照合する。

**48/48設定が合格し、独立照合1,824項目も全て合格**。
MC余裕を含む再構成判定値の最大は `2.130827%`、参照入力そのものの
再構成誤差の最大は `1.914327%`、Gamma標準誤差比の最大は `5.779211%`。
40設定はlambda=0.01、33節点Asianの4設定は0.0003、33節点の既知fixing付きAsianの
4設定は0.003を選択した。

### 旧3件と同じ評価標本での確認

追加で検証標本を元と同じ131,072ペアへ戻し、同じcounter `[0,131072)` の
入力AD平均・分散・寄与数が旧診断と完全一致することを確認した。
選択用262,144ペアは別区間であり、検証平均に混ぜていない。
33節点Asianでは両seedともlambda=0.0003を選び、以下の結果となった。

| seed | 旧lambdaと再構成誤差 | 新方式の再構成誤差 | MC余裕を含む判定値 | Gamma標準誤差比 |
|---|---|---:|---:|---:|
| 7 | 0.01: 6.63% | 1.3681% | 1.9313% | 10.9478% |
| 41 | 0.01: 7.96%、0.001: 3.65% | 2.2348% | 2.8300% | 8.1205% |

旧3件に対応する条件で新方式が3%基準を満たすことを確認した。
固定lambdaの失敗結果はそのまま保存しており、新方式の合格へ書き換えていない。
Gammaの正則化バイアスがゼロになった、または全ての成分が高精度に識別されたという
意味ではない。生のGamma質量と推定誤差を引き続き出力する。

結果と指紋は[機械記録](local-vol-gamma-selection-v0.1.json)に保持する。

## 回帰と限界

テストは標本区間の和の平均・分散、独立に再計算した判定、worker再現性、
notionalに対する判定の不変性、候補なし、検証失敗時の非再選択、無効ポリシー、
初期Gammaとの標本一致、通常価格の不変性を検査する。
検証2ペアの意図的な少標本ケースでは、再構成が良くてもGammaの誤差比が大きく、
`validation_failed` を返すことを確認した。具体例では再構成判定値が約0.87%でも
Gamma標準誤差比が約117%となり、選択値0.01のまま検証失敗を保存する。

Rust10テスト、Python VegaKT62テストが成功。最終バイナリで従来の固定lambda
独立照合372項目も成功し、生の観測・判定・価格差分・旧3件の品質失敗が以前の記録と
完全一致した。macOS arm64のLocal Vol replayも受入fixtureと完全一致。
Clippy警告0、整形・依存方向・差分検査も通過した。
手動数値CIへ新パネルを追加した。

この合格は正則化された有限基底解の成分検証である。
全時刻のGammaを式(4)・(9)へ結合した市場IVバケットと共分散、
非平坦スマイル、バリア、実市場でのヘッジ効果は未受入。
一般の多観測商品の一律合格を、この2観測の数値パネルから推論しない。
リモートCIとWindows実機は、この作業では実行していない。
