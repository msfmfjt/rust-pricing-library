# VegaKT バックテストの停止・再開検証 v0.1

日付: 2026-10-03  
状態: 想定される実行時エラーの保存・再開を実装し、検証合格。VegaKT の数値受入は未合格。

## 変更した動作

以前はデータ欠損やリスク品質違反で例外が発生すると、処理済み台帳を受け取れませんでした。
今回、停止理由と最後に完了した日までの記録を、再開可能な状態とともに保存できるようにしました。
[要件定義](../vega-kt-hedging-backtest-requirements-v0.1.md)第9節の failed 状態と、AC-10/14/15 の一部に対応します。

- 既定は `BacktestRunError` を送出し、`error.result` に失敗結果を保持する。
- `on_error="return"` は失敗結果を返す。どちらも失敗した日で停止する。
- CLI は失敗結果の JSON、CSV、checkpoint を書き出して終了コード1を返す。
- 停止理由、試行日、最終完了日、現金、残存建玉、未約定注文、処理率を記録する。
- 未処理の日の行を追加しない。完了日がゼロの場合の損益は null とする。
- failed / partial の最終ヘッジ誤差は null とする。
- 結果 JSON は version 2。旧 version 1 の読込み、入力・checkpoint の version 1 は維持する。

一日は、金利・配当、満期精算、前日の注文の約定、評価、翌日の注文決定をすべて完了してから確定します。
途中で想定されるエラーが起きた場合は、その日の台帳・建玉変更を取り消します。
失敗結果は**失敗した日の開始前**の状態であり、途中までの仮約定を確定約定として表示しません。
初期プレミアムと組成手数料は日次処理前に計上し、初日の失敗後も保持します。

## 検証

| ケース | 確認した内容 |
| --- | --- |
| 利息・前日注文約定後のリスク異常 | 現金、建玉、約定、注文状態が前日終了時に戻る |
| 時価評価後の solver 異常 | その日の台帳・リスク・意思決定が残らない |
| 初日の将来情報検出 | 損益が null、完了数ゼロ。再開時に初期プレミアムを二重計上しない |
| 複数契約の満期精算途中の欠損 | 先に処理した契約の精算も戻し、元の建玉を保持する |
| 最終ヘッジ清算の資金不足 | 清算を完了扱いにせず、修復後の再開と全期間再実行が一致する |
| 四戦略中の一部失敗 | 各戦略の状態と実際の coverage を保持する |
| 不正なネイティブ入力・数値エラー | 失敗した契約・日と原因を記録する |
| 実際のCLIで入力欠損→修復→再開 | 失敗時は終了コード1、修復後は0。結果JSONが全期間再実行と完全一致する |

## 再開の条件と残る課題

修正できるのは未処理日の市場入力です。処理済み入力、日程、契約、設定、provider、実装が変わると
checkpoint を拒否します。今回も実装hashが変わるため、以前の実装で生成したcheckpointの再利用はできません。
日程や契約自体の修正は全期間の新規実行が必要です。

不正な初期入力、初期資金不足、不正checkpoint、providerの構築失敗、想定外のプログラム例外は、
今回の失敗レポートの対象外であり、例外を返します。プロセス強制終了、ディスク書込み失敗、
外部providerの状態の巻戻し、hold_positions による継続は実装していません。

リスク計算の診断利用ガードは維持しています。
[前回の数値検証](vega-kt-backtest-allocation-audit-v0.1.md)では154項目中54項目が不合格でした。
今回は数値受入パネルを再実行しておらず、台帳の停止・再開の合格は論文VegaKTの受入を意味しません。
論文に沿ったガンマ復元・伝播の接続には、引き続き本文の式の照合が必要です。
