# RQMCの通常バックテスト接続と追加受入

RQMCの通常バックテスト接続を実装し、未使用seedの40ケースと保存・再開を検証した。
年間用の30銘柄は個別の数値判定に合格したが、保有ポートフォリオの誤差上限で停止した。

通常の `RustPricingProvider` でRQMCを明示的に選択し、個別リスク、商品間の推定共分散、
保有・発注予定ポートフォリオの精度検査、保存・再開まで同じ推定方式を使用する。
許容誤差、Gamma回復・条件付きADの判定、計算量上限は変更しない。

## 使用方法

```python
provider = RustPricingProvider(
    numerical_scope="multi_step_custom_basis_gamma",
    variance_basis_policy="coupled_row_hats",
    sampling_policy="rqmc_path_16_scrambles",
    worker_threads=4,
)
```

`sampling_policy="rqmc_256x16"` は全商品256点、16スクランブル。
`sampling_policy="rqmc_path_16_scrambles"` は6区間の算術Asianだけ128点、他は256点。
いずれも入力の `engine.type="randomized_quasi_monte_carlo"`、
`variance_reduction={"antithetic": true, "brownian_bridge": false}` が必要。
入力の点数を暗黙に変更したり、失敗したseedを自動交換したりしない。

CLIでは、校正方式の指定に `--rqmc-path-16-scrambles` または `--rqmc-256x16` を追加する。
指定できる校正方式は `--validated-custom-basis coupled_row_hats` と
`--validated-put-extension all_rows`（Call限定の `--validated-extension all_rows` も可）。
`linear_time` と他の名前付きbasisへのRQMC拡張は受け付けない。
RQMC指定を省略した既存の疑似MCの最低サンプル数・判定は維持する。
sampling policyと並列数はcheckpointの実装IDに含まれる。更新前のcheckpointは拒否し、
保存済みinputから再計算する。CLIの既定並列数は1、`--worker-threads 4` で4に指定できる。

## 精度の扱い

独立単位はSobol点ではなく16個のスクランブル平均。平均の共分散はサンプル共分散を16で割る。
点数の異なるAsianとEuropeanでも、同じスクランブル番号を対応させて商品間共分散を作る。
既存の保有・丸め後発注予定ポートフォリオの数量、契約倍率、非対角共分散を含む精度検査を適用する。

検証状態は `runtime_checked_multi_step_rqmc` と明示する。独立受入は以下の実測範囲に限定され、
すべての市場・商品に対する数値受入を意味しない。とくにcoupled basisの価格差分検証だけで
all_rowsの経路依存商品を独立受入したとは扱わない。

## 証拠の区別

- [以前の未使用seed検証](vega-kt-holdout-v0.1.md)にある疑似MCの8件の失敗は保持する。
- 4区間：10商品 × seed 100003 / 100019。256点 × 16スクランブル。
- 6区間：初回の256点設定はAsianで計算量上限に達した。失敗ログを保持する。
- 6区間の別設定：Asian128点、他256点 × 16スクランブル。seed 100043 / 100049を実行前に固定。
- 上記の価格、2段階のIV価格差分、合同共分散、spot・IV・複合変化によるP&Lを検証。
  独立価格参照は過去に封印した同一市場・同一payoff・同一basisの参照値を再利用。
- 年間用all_rowsの初日30銘柄には、別途独立価格参照と2段階の再校正価格差分を新規計算。
  対象はこの初日のEuropean Callだけ。

数値計算当時の入口3ファイルは `provider-256-source.tar.gz` に保持する。最終的な128点の入口追加については、
数値計算本体・校正・共分散・誤差判定が変わらないことをソース比較で確認し、
最終ソースによる混在点数の通常バックテストと保存・再開も別途検証した。

## 範囲

年間用の試行は252日分の入力から冒頭2日を実行する設定で開始したが、初日の精度検査で停止した。
年間全体の完走、隔離された環境での速度測定、
実市場でのヘッジ効果はこの試行では確定しない。推定共分散は市場リターンの共分散ではなく、
校正誤差・離散化誤差・Deltaの推定誤差も含まない。

## 検証結果

| 対象 | 結果 |
|---|---|
| 4区間、10商品 × 2新seed | 20/20合格、519検査失敗0 |
| 6区間、10商品 × 2新seed | 20/20合格、719検査失敗0 |
| 上記の損益シナリオ | 24/24合格（上記検査数に含む） |
| 年間初日all_rowsの独立参照作成 | 601検査合格 |
| 年間初日30銘柄と独立価格差分の照合 | 960検査合格 |
| Companionの回帰試験 | 288件合格 |
| 実ネイティブの経路依存商品バックテスト | 完走、保存・再開一致、意図的な受入失敗時の注文抑止を確認 |
| 配布wheelのCLI | 中断状態・完了状態からの再開がAPI結果とバイト単位で一致 |

実バックテストはAsian128点とEuropean256点を混在させ、16スクランブルの共分散を検査。
保有リスクの最大バケット標準誤差は初日0.79564、翌日0.65076（上限10）。
固定strikeのIV損益説明1区間を検証し、満期区間は明示的に説明対象外とした。
wheel内の37 Pythonファイル・26スキーマは、最終ソースとのバイト一致を確認した。

### 年間用ポートフォリオ

同じ252日分の入力、10保有銘柄・20ヘッジ候補、all_rows、solver上限100,000回、
許容誤差1e-8、ridge1e-4、合同SE上限10を使用した。変えた数値設定はRQMCの256点 × 16スクランブルとseed。
30個別リスクと合同リスクのネイティブ判定は通過したが、初日の保有ポートフォリオSEが
**20.81222 > 10**のため、日次状態をロールバックした。完了日数0、注文0。
以前の疑似MC試行の36.04708からは低下したが、年間受入は未完了。

今回の計算時間は1221.18秒。別の数値検証と同時実行しており、隔離した速度測定でも
年間計算時間の予測でもない。失敗した日の合同リスクも保存したため、数量を反映した誤差を追跡できる。

証拠は `benchmark-results/vega-kt-rqmc-provider/` に保存した。
`validation-source-at-run.tar.gz` は数値試行当時のソースを再現し、
最終ソースは `source.tar.gz` に保存する。過去の失敗ログ・参照結果は変更していない。

### 512点の探索的な追加試行

同じseed 100003、同じ保有10銘柄・数量で、点数だけ512に増やした。
10商品のネイティブ受入は合格したが、保有ポートフォリオSEは **11.92913 > 10** で失敗。
計算時間442.55秒。これは既に結果を見たseedを使う探索試行であり、独立受入へ昇格しない。
発注予定の20ヘッジ候補、年間再生はこの512点試行の対象外。
通常providerの公開sampling policyへ512点は追加していない。

残件は、上限10を満たす設定を未使用seedで確認し、発注予定ポートフォリオを含めた
通常処理で再受入すること。その後に年間全体の完走と計算時間を測定する。
