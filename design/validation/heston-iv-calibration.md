# Exact Black-IV calibration and SSVI adapter validation

## Frozen pre-run protocol

`fixtures/rough-volatility/iv-calibration.json` records all inputs, starts, bounds,
grids, targets and thresholds before the first numerical run. The independent
checker locks those inputs and the unchanged parent Fourier fixture's hash.

Four fast integration tests exercise 72 call/put Black target conversions and
constant-variance IV/Jacobian comparisons; six-direction rough and five-direction
lift chain-rule/quote-order/scale comparisons and two parameter bump sizes;
42 SSVI queries across both shapes, interpolation and extrapolation; and explicit
bad-input, invalid initial price, active-bound and evaluation-budget behavior.
Two internal unit tests cover Black inversion, parity, Vega and numerical-domain
rejections. None of these tests certifies all deep-wing/short-expiry IVs.

## Independent evidence

The Python checker uses erfc Black prices and Brent inversion, independently of
production's rational-CDF, normalized-OTM bisection and bindings. SSVI references
use SciPy PCHIP and the direct SSVI formula (high precision for the Heston-like phi).
There are 36 Black rows (both option sides and Vega), 42 SSVI queries, and 12 IVs
inverted from the independent parent ordinary-Heston/three-factor-lift prices.
No production extension is imported by that reference checker.

The ordinary-Heston and lift fits use those independent IV targets, with five
free parameters. Rough recovery uses nine IVs generated by the same finite-grid
production model; its six-parameter recovery is an optimizer/chain-rule check,
not an independent continuous-time rough price oracle. Two starts per family
are retained. SSVI is a separate nine-quote model-mismatch experiment, also with
two starts and six free rough-Heston parameters.

All quotes use F=100 and D=.97, with iv_scale=1. The common parameter vector is
v0=.04, kappa=.7, theta=.055, nu=.18, rho=-.65; rough H=.1. The explicit lift has
weights [.2,.4,.5] and rates [.1,1,8]. Starts and bounds are retained in the fixture.
Markov maturities are .25/1 years and strikes80/100/120; rough/SSVI maturities are
.25/.75/1.5 and strikes85/100/115. SSVI uses theta=.04*T, rho=-.5, eta=.35, gamma=.5.

## Numerical acceptance and interpretation

Calibration uses128 Riccati steps,512 frequency intervals,cutoff128, at most60
iterations/100 evaluations. Exact/recovery fits require all absolute IV residuals
<=2e-6 (0.02 IV bp). Final models are re-evaluated at256 steps/1024 intervals/cutoff256,
and their maximum target IV error must be<=0.0005 (5 IV bps). This combined
refinement changes both time and cutoff; it does not separate their error sources.

SSVI is not assumed to be a Heston surface. Its separate pre-run criteria require
objective<=half the starting objective and maximum fine-grid IV error<=0.005
(50 IV bps), without forcing `fit_achieved=true`. The stricter solver fit flag is
still checked against every scaled residual, not inferred from termination.

All eight first-run experiments passed their respective criteria. The SSVI runs
stopped at projected-gradient tolerance with H on its declared0.02 lower bound.
They did **not** meet the2e-6 residual tolerance; `fit_achieved=false` is correct.
The largest fine-grid SSVI target difference was8.361397956602e-5, about0.83614 IV bp.
That observed value does not tighten or replace the pre-run acceptance thresholds.

See retained `IV_FIT` and `IV_REPRICE` log rows for full parameters, evaluations,
objective changes and all quote-level errors. Parameters at active bounds are
not estimates of unconstrained optima. A small fit error is neither parameter
identification nor an economic model-quality certificate.

## Gates and provenance

`.github/workflows/heston-iv-calibration.yml` executes independent references,
protocol mutation controls and debug/minimal/release Rust checks on three OSes.
The release target explicitly includes the ignored numerical panel and retains
`heston-iv-calibration.log`; missing artifacts are errors. The source-archive guard
requires those gates and the wheel example. Python tests require every new public
class/member and exercise frozen results, units, SSVI and invalid input behavior.

An initial baseline-workspace run was started from the restored parent source,
then reached rustdoc after the new binding file had been introduced. Rustdoc
therefore saw mismatched parent-library/new-binding snapshots and failed. That
mixed-snapshot run is retained and is not counted as a successful baseline. Final
workspace validation is rerun serially against a frozen source tree. The first
IV unit/integration and numerical runs themselves passed without budget changes.

Source additions leave parent price/Riccati/risk formulas, RNG, schemas and Cargo
manifest/lockfile unchanged. The only parent-code changes are sibling visibility
for existing helpers plus module exports. Local wheel tests use the supplied
pinned compiler and offline vendored sources; system-site-package inheritance is
reported rather than described as a clean install. Remote CI results must be
reported for the actual published commit, never inferred from parent success.

Clippy initially rejected the Python IV-quote constructor's eight Rust arguments
(including its Python token). The token is now acquired inside the constructor;
the Python signature and numerical checks are unchanged. No lint was suppressed.
