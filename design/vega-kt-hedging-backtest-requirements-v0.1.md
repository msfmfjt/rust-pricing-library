## 1. 目的と判定対象

VegaKT を用いて満期・ストライク別のボラティリティ感応度をバニラオプションでヘッジし、デルタヘッジ等に対する追加効果を、取引費用控除後のヘッジ誤差と残存リスクで比較する。

本機能は、各時点で入手できた情報だけを使い、価格・リスク計算、ヘッジ数量決定、仮想約定、資金勘定、商品イベント、満期精算を再現する。VegaKT のゼロ化と実現損益のゼロ化は同じ受入条件にしない。ジャンプ、離散リバランス、モデル誤差、約定遅延、費用、ヘッジ不能なリスクを残存要因として測定する。

検証する問いは次のとおり。

- デルタのみ／単一ベガのヘッジに対し、損益の分散、RMSE、裾の損失がどう変わるか。
- 満期・ストライク別ヘッジの改善が、売買回転と取引費用に見合うか。
- ヘッジ商品数、リバランス間隔、流動性制約、VegaKT の数値誤差にどの程度依存するか。
- スマイルの平行移動、スキュー・曲率変動、スポット急変に対し、どのリスクが残るか。

## 3. 既存実装との接続と不足機能

| 確認できた資産 | 利用方針／追加要件 |
| --- | --- |
| `PricingRequest` / `PricingPlan` / `PricingResult`、Python API、JSON、fingerprint | 各日・各商品の価格／リスク計算に再利用する |
| Local Volatility の VegaKT、raw / market-scaled、分解残差、境界診断 | 数量決定の入力とし、数値品質による売買可否判定を追加する |
| Local Volatility の Spot bump と共通乱数 | 実際の bump semantics を記録し、対象とヘッジで一致させる |
| 一部 LSV 系の Market-IV VegaKT | 初期対象に混在させず、別の risk basis として後日接続する |
| Asian の既知 fixing、Lookback の履歴極値 | 期中再評価アダプタの再利用候補。日付経過時の状態更新が必要 |
| 過去 monitoring 日を持つ Barrier を拒否する validation | Barrier の継続状態・ノックアウト・確定支払の引継ぎが追加実装の前提 |

新規機能は、市場履歴の再生、商品マスター／状態管理、リスク基底の検証、ヘッジ数量最適化、約定シミュレータ、現金台帳、比較レポートである。既存の単日時点の価格計算だけでヒストリカル・バックテストが完成するとは扱わない。

特に現行 LV の Spot bump は Local-variance grid を保持して forward normalizer 等を再構成する経路である。`smile_dynamics` の文字列だけから sticky-strike 等の再校正挙動を推定しない。H0 で実計算の convention を確認し、未対応の組合せは拒否する。毎日の観測サーフェス更新と、同一時点で Delta を計算する bump convention は別の設定とする。

## 4. VegaKT の意味・単位・座標 [P0]

### VKT-01: リスク方式を明示する

少なくとも次の二種類を区別する。

1. **LV paper decomposition**: SSVI/eSSVI から得た Local Vega を、論文方式で満期・log-forward-moneyness の reporting basis に分解した値。独立に bump 可能な市場 quote の一意な勾配とは解釈しない。
2. **Market-IV quote gradient**: 保持した入力 IV grid と所定の補間・再校正計算に対する導関数。モデル、補間、固定する変数、校正 reverse の範囲を伴う。

P0 は 1 を採用する。2 の接続時には `risk_method`、`basis_id`、補間方式、校正方式、座標系、固定する入力を別途 version 管理し、方式が異なる列を同じヘッジ行列に混在させない。

### VKT-02: 共通基底と単位

- 同じ時点の対象ポートフォリオと全ヘッジ候補は、同じ reporting basis、IV の定義、通貨、規格化で評価する。
- Raw は「通貨 / absolute volatility 1.0」、market-scaled は raw × 0.01、すなわち「通貨 / 1 vol point」とする。内部計算は raw に統一し、表示時に換算する。
- 配列は `[maturity][log_forward_moneyness]` の row-major。軸、shape、単位、contract multiplier を必須にする。
- reporting maturity の絶対日付、評価日からの残存年数、`k = log(K / F)` を保存する。IV 座標変換がある場合は元の physical strike と変換後 strike を両方持つ。
- 一つの建玉は固定された契約 ID・strike・expiry で追跡する。翌日も「ATM bucket」を保有しているという扱いで strike を自動変更しない。契約の入替えは必ず売買として計上する。
- 共通基底を各 pricing request に正しく供給できることを実装前の適合条件とする。商品ごとに異なる grid の同じ index を足さない。基底を変更する場合は、risk の変換則と保存誤差を明示する。

### VKT-03: 対象とヘッジ商品の対応

対象の VegaKT と、候補オプション一単位の VegaKT を同じ計算法で計算し、ヘッジ感応度行列を作る。バニラの解析 Vega と補間重みで近似する高速化は、この行列との一致が検証された場合のみ認める。

「bucket Vega ÷ vanilla Vega」で個別数量を決める方法は、一商品一 bucket の対角対応が成立する検証例に限定する。一般のサーフェス補間、異なる満期、非対角感応度では行列として扱う。

### VKT-04: 残差と不確実性

- `pre_projection = sum(raw_buckets) + signed_residual` の既存規約を保持する。
- 密度閾値による除外、edge への配賦、Local variance の floor/cap、標準誤差、利用可能な共分散を保存する。
- 異なる原因の残差（分解残差、ヘッジ後の bucket 残差、P&L 説明残差）を別項目として扱う。
- 分解残差を近傍 bucket に移してゼロと報告しない。符号付き残差の集約に加え、商品別残差の絶対値合計も保存し、相殺で問題が隠れないようにする。
- 閾値超過時は事前設定した `fail_run` または `hold_positions` を適用する。厳格モードの既定は `fail_run`。古い Greeks による新規売買への黙示的な切替えはしない。
- 標本分散と推定平均の標準誤差を区別する。必要な共分散がなければ独立と仮定して合成 SE を作らず、利用不能と表示する。MC/RQMC の SE はモデル誤差・時間離散化誤差の評価とは区別する。

## 5. 入力データと将来情報の排除 [P0]

| 要件 ID | 必須内容 |
| --- | --- |
| DATA-01 | 市場スナップショットに `snapshot_id`、観測時刻、利用可能時刻、タイムゾーン、source、revision、品質フラグを持たせる |
| DATA-02 | 原資産価格、金利・配当入力、校正済みサーフェス、候補・保有商品の bid/ask、満期 settlement 値を供給する |
| DATA-03 | 商品マスターに固定 contract ID、原資産・通貨、call/put、strike、expiry、payment date、multiplier、lot、上場／終了日を持たせる |
| DATA-04 | 当時存在し取引可能だった契約から候補を選ぶ。将来上場銘柄、後から判明した出来高、将来の清算値で選別しない |
| DATA-05 | スポット・曲線・surface・option quote の時刻差に上限を設ける。bid > ask、非有限値、重複 ID、不正日付、期限切れ quote は検出する |
| DATA-06 | 校正結果は使用 quote の cutoff、入力 hash、校正／補間 version、誤差、制約診断を持つ。将来分も含めた全期間一括 fit は禁止する |
| DATA-07 | 取引日、休場日、日数計算、イベント時刻、配当権利落ちと支払日を明示する。P0 pricing 時間は既存 Act/365F に合わせる |
| DATA-08 | 既存保有商品の quote が候補集合から消えても、建玉を消さない。保有商品の評価・決済データは最後まで必要とする |

戦略が参照できるデータは、`available_at <= decision_time` のものに限る。改訂後系列しかない場合は、その限界を manifest と結果に明記し、「当時入手可能な情報だけによる検証」の適合判定から除外する。

欠損時の既定は停止。任意の継続モードでは、新規売買を止め、保有数量を維持し、事前に指定した model mark 等で評価する。補完法、staleness、利用不能期間を保存する。未来の値で補完しない。戦略比較では共通の評価期間・欠損方針を使用し、各戦略で不利な日だけを削除しない。

現金配当を含む physical-IV 履歴を canonical IV とみなして入力しない。P0 の対象外データは validation で拒否する。配当対応を追加する場合は、価格／strike の変換、forward の再構成、Delta の convention、権利落ち・受払台帳を一組で検証する。

## 6. 時点進行・評価・約定 [P0]

### TIME-01: 先に意思決定、後に約定

初期のヒストリカル標準設定は「営業日 d の cutoff までの情報で注文数量を決め、次営業日の設定された約定時点に約定させる」とする。数量は約定価格を知る前に固定する。約定時点の quote はシミュレータだけが参照できる。EOD のみなら次営業日 EOD の仮想約定と明示し、当日終値を見て同じ終値で即座に約定する設定にしない。

同一スナップショットで意思決定・mid 約定する実験は `frictionless_research` と表示し、遅延・費用ありの結果と分ける。bid/ask 約定も execution model 上の仮定であり、実際の市場で約定した記録とは扱わない。

### TIME-02: イベント順序

各イベントを時刻順に処理し、同時刻の順序を policy として保存する。日次標準では次を明示する。

1. 前回からの現金利息・借株料・配当権利／受払を更新する。
2. 観測 fixing、満期、確定支払等を契約の時刻順で処理する。
3. 以前に決定済みの注文を、約定可能性・期限・数量制限を検査して実行する。
4. 保有資産・負債・現金・未払受取を評価し、損益を記録する。
5. 当該 cutoff までに利用可能となった情報で再評価・リスク計算し、次の注文を作る。

同日に満期した契約への注文は失効させる。イベント、約定、評価が同時刻に置かれる場合の優先順を fixture 化し、実装依存にしない。既存 pricing の配当と満期の順序にも整合させる。

### TIME-03: 各日のモデル更新と mark

- 毎日、観測された校正済み surface・曲線・残存期間から pricing plan を構築する。過去日の surface に将来の calibration を遡及適用しない。
- 市場 mark とモデル mark を分ける。対象の市場価格がない場合は model-mark P&L と表示する。ヘッジの費用・実現損益は約定価格に基づく。
- 同じモデルで生成・評価した実験と、異なるモデル／ヒストリカル市場の実験を区別する。
- ランダムな市場生成にはスポットだけでなく整合的な option quote/surface の時系列を含める。将来経路を見て当日の IV を作らない。外側の市場経路生成と内側の価格計算の乱数を分離する。
- 生成過程の確率測度・ドリフトを記録する。リスク中立測度下の模擬実験の統計を、そのまま実市場での損失確率と解釈しない。

### TIME-04: 商品状態と終了

契約の満期 payoff、確定した未払金、payment date を別管理する。残存期間がゼロになった商品を MC に再投入せず、契約ルールで精算する。P0 例は満期と支払日を一致させる。異なる場合は確定債権・債務を支払まで維持する。

通常は対象の最終支払まで実行する。途中終了時は `mark_to_market` または `liquidate_all` を明示し、前者には未決済建玉、後者には対象・ヘッジ双方の実行可能な清算価格と費用を含める。対象の清算価格がない model-mark 途中終了を、実現済み最終ヘッジ誤差と表示しない。

## 7. 戦略とヘッジ数量 [P0]

### STRAT-01: 比較する四戦略

| 戦略 | 保有・更新ルール |
| --- | --- |
| Unhedged | 対象ポジションと現金のみ |
| Delta only | 原資産でポートフォリオ Delta を相殺 |
| Delta + scalar Vega | 一つの事前指定ルールで選ぶ流動性のあるバニラ等で scalar Vega を相殺後、Delta を調整 |
| Delta + VegaKT | 複数バニラで bucket risk を縮小後、Delta を調整 |

scalar Vega は採用する VegaKT の bucket 和とし、分解残差を黙って加えない。比較には同一対象、初期取引条件、市場系列、decision/fill 時刻、費用・資金条件、評価方法を使用する。自己銘柄と同一のバニラによる完全相殺は検算用 fixture に限定し、実用比較では同一契約を候補から除く設定を標準にする。

### STRAT-02: 数量と符号

対象ポジションは signed quantity `q`（買い正、売り負）を持つ。以下の `v` と `d_target` は quantity と multiplier を一度だけ反映済みのポートフォリオ感応度とする。

- `v ∈ R^B`: 対象の bucket VegaKT。
- `A ∈ R^(B×N)`: 列 j がヘッジ契約 j 一枚当たりの bucket VegaKT。multiplier を含む。
- `h ∈ R^N`: 取引後に保有するヘッジ枚数。注文量は `Δh = h − h_prev`。
- `d_j`: ヘッジ契約 j 一枚の Delta。`n` は原資産の保有単位。

ヘッジ後 bucket risk は `r = v + A h`。原資産 Delta が 1 の場合、目標保有量は次式とする。

```text
n* = −(d_target + sum_j h_j d_j)
```

これは意思決定時の目標であり、約定遅延後までゼロ Delta を保証しない。整数化・不成立による実保有量を記録し、約定後の Delta と VegaKT を再測定する。将来の約定時点の Greeks を遡って注文量に使わない。

### STRAT-03: 数量最適化

初期方式は制約付き重み付き最小二乗とし、例えば次の version 化した目的関数を採用する。

```text
min_h  || W (v + A h) ||²
     + λ || L h ||²
     + η sum_j c_j |h_j − h_prev,j|
```

`W` は bucket の重みまたは明示的な IV shock scale、`L` は保有量の規格化、`c` は意思決定時に既知の費用推定。各項の単位・規格化と `λ, η` を保存する。P0 標準は一様な 1 vol point shock の尺度を使い、将来データから推定した重みは使わない。推定費用と実際の台帳費用は別に記録する。

以下を必須とする。

- ポジション上限、総額／資金枠、short 可否、lot、日次売買上限、最低 Vega、残存期間・spread・staleness の候補制限。
- rank、condition number、特異値 cutoff、正則化、solver termination、制約違反、hedge residual の保存。
- 解が複数のときの決定的な tie-break。ヘッジ候補の並び順を契約 ID 等で固定する。
- 連続解を lot に丸めた後、制約を再検査し、Delta を再計算する。丸めで資金制約を破る解は約定させない。
- 特異・ill-conditioned・実行不能時の明示的な `fail_run` / `hold_positions`。制約を自動的に緩めない。
- 新規候補と既存保有契約の和集合を扱い、候補から外れた既存建玉も risk に含める。売買不能な既存契約には `h_j = h_prev,j` を課すか、その固定感応度を対象側に加える。候補除外を建玉消滅として処理しない。
- ヘッジを弱める turnover penalty がある場合、毎回 residual が減ることを強制しない。最適化前後の目的関数と residual を両方報告する。

W の推定、正則化、候補選定のパラメータ調整は学習／検証期間内で行い、最終テスト期間を固定する。ローリング推定も過去データだけで実施する。

## 8. 約定・資金勘定・損益 [P0]

### PNL-01: 売買と費用

買いは ask、売りは bid を基準に、明示的な slippage と手数料を加える。market-mid に対する spread/slippage コストは説明項目として保存するが、bid/ask 約定価格で既に現金控除した分を再び控除しない。候補オプションのプレミアム、原資産代金、借株料、利息、配当、settlement を別 entry にする。

借入・貸出金利は別入力を許し、同一金利を使用する場合も明記する。ショート現物は借株可能量と費用を必要とし、配当支払義務を反映する。日中に金額が変わる場合はイベント間ごとの残高に利息を付ける。評価用 discount curve と、現金の funding curve は区別する。

### PNL-02: 自己金融の台帳

`C` を現金、`U` をヘッジ価格、`m` をヘッジ multiplier とする。各約定で次を満たす。

```text
C_after = C_before
        − Δn × S_exec
        − sum_j Δh_j × m_j × U_exec,j
        − explicit_fees
```

取引以外では、実際の受払 cashflow、利息、借株料でのみ `C` を更新する。外部入出金は専用 entry とし、損益から除外する。資金枠を超える際に、現金を任意に補充して実行を続けない。

対象組成時のプレミアムは signed quantity に対応する反対符号の現金として記録する。期中開始の場合も初期 cash、取得原価、時価の関係を記録し、初期 day-one mark 差をヘッジ効果に混ぜない。

### PNL-03: 損益の定義

ポートフォリオ価値は次のとおり。`R` は他の価格項目に含めていない確定未払の純受取現在価値。

```text
E_t = C_t + V_target,t + n_t S_t + sum_j h_j,t m_j U_mark,j,t + R_t
P&L_(a,b) = E_b − E_a − external_net_cash_inflows_(a,b)
```

`V_target` は signed position value。payoff が `R` に移ったら対象価値から除き、支払時に `R` を消して現金へ移す。オプションの価値、満期 payoff、確定受取金を二重計上しない。

日次総損益、累積損益、対象、オプションヘッジ、原資産、費用、funding、配当・決済の寄与を出す。実現／未実現の表示には平均取得単価等の cost-basis policy を固定し、その合計は総損益に照合する。

初期純資産がゼロで、全契約が精算済み、外部資金移動がなければ、最終現金が signed hedging error となる。その他は初期資本と資金移動を調整した定義を使用する。比較用に指定通貨の money-market account `B_t` を共通 numeraire とした割引後誤差も出力する。

割引後の誤差は `E_T/B_T − E_0/B_0 − sum_i external_net_cash_inflow_i/B_i` とし、外部入出金ごとにその時点の numeraire を使う。対象の受払やヘッジ売買は既に自己金融台帳に含まれるため、ここで再び引かない。

### PNL-04: リスクによる説明と実測損益

`Delta × ΔS`、`0.5 Gamma × (ΔS)^2`、`VegaKT · ΔIV` 等は説明用近似とし、台帳の実測損益を置き換えない。Theta、曲線、配当、交差項・高次項、数値誤差を residual に残す。

日を跨ぐ IV 差には満期ロールと strike/moneyness の座標移動がある。同一 index の IV 差を直接内積せず、同一の絶対満期・strike または明示した共通基底へ合わせ、採用した Delta convention に整合させる。P0 では正確な成分別台帳照合を必須、完全な Greeks attribution は P1 とする。

## 9. 出力と評価指標 [P0]

一回の実行について以下を保存し、Python で読み戻せること。

| 出力 | 内容 |
| --- | --- |
| Run manifest | 入力データ／設定 hash、code revision、未コミット変更の識別情報、モデル／schema／policy version、日時、乱数 seed、実行環境 |
| Daily ledger | 市場 mark、対象価値、実保有量、現金、未払受取、日次・累積損益、資金・取引費用 |
| Orders / fills | decision/fill 時刻、対象契約、目標／注文／約定数量、価格、費用、拒否・失効理由 |
| Risk snapshots | 共通 bucket 軸、ヘッジ前後 Delta/VegaKT、分解残差、SE、edge 診断、数値品質 |
| Solver diagnostics | 候補集合、行列識別情報、rank、condition、正則化、目的関数、制約、丸め後残差 |
| Strategy comparison | 四戦略の同条件比較、データ coverage、失敗・停止件数 |

実行状態は `completed` / `partial` / `failed` を明示する。停止した日以降の損益をゼロで埋めて完走扱いにせず、停止理由・最終処理時刻・残存建玉を出力する。

表形式データは CSV、再実行に必要な設定・構造化情報は version 付き JSON を P0 の標準とする。Parquet は任意の追加出力。欠損・未計算は `null` 等の明示表現とし、ゼロに変換しない。

評価指標を次の二群に分ける。

- **一つの履歴系列**: 累積損益、日次損益の平均・標準偏差・RMSE、累積損益の金額ベース最大 drawdown、最悪日、売買回転、総費用、残存 bucket risk、ヘッジ不能領域。
- **複数の満期取引／独立シナリオ**: 最終 hedging error の平均・標準偏差・RMSE、損失の分位点と ES、信頼区間。損失は `−hedging_error` と定義し、例えば 95% / 99% の水準を設定として保存する。

同一履歴の日次値や重複する取引期間を独立な最終誤差サンプルとはみなさない。サンプル数、重複、block bootstrap 等の推定方式を表示し、裾のサンプルが不足するときは指標を参考値または算出不能とする。初期資本ゼロの自己金融ポートフォリオに無定義の percentage return / Sharpe を計算しない。

ヘッジ改善率は `1 − Var(error_VegaKT) / Var(error_Delta)` 等を定義して出す。比較母集団と費用条件を揃え、分母がゼロ／極小の場合は算出しない。成績の改善そのものはソフトウェアの必須受入条件としない。

## 10. 再現性・性能・API [P0]

- 市場生成、校正、価格推定、戦略比較に使う乱数 domain を分離する。戦略の比較には同一の外側市場パスを用い、内側の共通乱数利用も明示する。
- 同一入力・同一対応環境で再実行した場合、既存 engine の再現性規約を継承する。異なる環境には所定の許容誤差を使用し、無条件の bitwise 一致を約束しない。
- リスク感応度による数量が MC seed に過敏でないことを別 seed と sampling refinement で評価する。価格計算 SE と、バックテスト損益分布の推定誤差を別表示にする。
- 設定・市場・商品状態・risk basis・engine policy を含む cache key を使う。変更後の surface に旧 Greeks を再利用しない。
- 日次 checkpoint から再開でき、再開前の注文・約定・cashflow が二重計上されないこと。
- 既存 pricing request/result の wire semantics を変更しない。バックテストには別の version 付き request/result を設ける。
- Python の想定入口は `run_backtest(config, market_history, portfolio)` とし、validate、実行、結果出力を分離する。この名前は提案であり、既存 API ではない。
- 数値計算は既存 Rust エンジンを使用する。日付進行・データ処理・最適化を Python／Rust のどちらに置くかは H0 で決める。Rust の private engine に外部から依存しない。
- 性能評価用に「252 営業日・対象 10 建玉・候補 20 契約・VegaKT 5×9 buckets」の代表 workload を用意する。評価回数、全実行時間、日次 p50/p95、peak memory、I/O を測る。
- 数値品質を固定した上で H0 に対象機材・path 数・時間／メモリ予算を決定する。任意の秒数を性能要件として先に断定しない。予算を満たさない場合、精度設定を黙って下げない。

## 11. 受入基準

各試験には version 付き入力、期待結果、許容誤差、実行環境を持たせる。`abs_tol + rel_tol × scale` の scale と閾値を事前に固定する。初期の決定的な台帳 fixture では通貨単位 `abs_tol=1e-10`、`rel_tol=1e-12` を提案し、実データでは通貨最小単位・丸め規約を別途設定する。

| ID | 試験 | 合格条件 |
| --- | --- | --- |
| AC-01 | 無取引・無価格変動・無費用・ゼロ金利 | 全期間の損益ゼロ、台帳保存則成立 |
| AC-02 | 自己金融の手計算例 | 売買、利息、配当、満期、未払受取を独立計算した cash / equity と一致 |
| AC-03 | 同一バニラの反対建玉 | 同数量で価格・Delta・VegaKT・payoff が相殺。費用ありでは既知の費用・funding が残る |
| AC-04 | 一 bucket の解析解 | 対角例の `h = −v/A`、必要な原資産数量、multiplier・short の符号と一致 |
| AC-05 | 複数 bucket の既知行列 | full-rank の完全ヘッジ、rank-deficient の最小残差、上限・lot の結果が独立計算と一致 |
| AC-06 | 1 vol point と単位変換 | raw と market-scaled を正しく換算すれば同じヘッジ枚数。multiplier の二重掛けがない |
| AC-07 | VegaKT の意味・基底 | bucket 和＋分解残差の照合、共通軸の一致。LV は論文方式に整合する perturbation で検証し、SSVI 生成 node の独立 quote bump に置換しない |
| AC-08 | 先読み検出 | 意思決定後に初めて利用可能となるデータを変更しても、それ以前の注文は不変。校正・候補選定にも適用 |
| AC-09 | 費用計上 | 固定注文を replay すると、bid/ask、slippage、手数料が期待どおり cash に反映し二重控除されない |
| AC-10 | 満期・休場・欠損 | 期限切れ注文の失効、正しい支払、stale quote 拒否、保有商品の欠損 policy が仕様どおり |
| AC-11 | Black–Scholes 極限 | 定数ボラの LV を既存 BS 解析値に価格・Delta 等で照合。費用ゼロの模擬実験で刻み縮小時のヘッジ誤差分布の収束を統計的に確認 |
| AC-12 | 不安定行列／低 Vega | 条件数・閾値を報告し policy を適用。NaN、無限数量、無記録の制約緩和を出さない |
| AC-13 | 数値品質 | path 数、時間刻み、grid、seed の変更に対する数量・P&L の安定性を事前の許容差で確認。SE 超過時に policy 発動 |
| AC-14 | 再実行・再開 | 同環境で再現性規約どおりに一致し、checkpoint 再開で取引・利息・payoff の重複がない |
| AC-15 | 戦略比較 | 四戦略が同一条件・期間で完走し、費用控除前後、coverage、残存リスクを同じ定義で比較できる |
| AC-16 | データ不足 | quote/surface の由来・利用可能時刻・必要な settlement がない実験を、適合済みヒストリカル検証と表示しない |

AC-11 は一つのランダム経路で常に誤差が単調減少することを要求しない。AC-09 は注文固定時の会計試験であり、費用によって戦略の注文自体が変わる場合に損益の単調性を要求しない。AC-13 の数値閾値は H0 で fixture ごとに固定し、試験結果を見て緩めない。

## 12. 実装段階と完了条件

| Gate | 内容 | 出口条件 |
| --- | --- | --- |
| H0 | 対象市場・データ契約、VegaKT/Delta の実際の意味、共通基底、時点順序、許容誤差を固定 | 計算例・入出力例・制約・性能予算がレビュー可能。API の不足を列挙 |
| H1 | replay、契約マスター、資金台帳、満期精算、無ヘッジ／Delta | AC-01/02/08/09/10、先読み検出と手計算 fixture が合格 |
| H2 | VegaKT 行列、制約付き solver、scalar 比較、数値品質判定 | AC-03〜07/12/13 が合格 |
| H3 | 四戦略の統合、成果物、再開、合成データでの全経路試験 | AC-11/14/15、runtime/memory 報告、実行例が完成 |
| H4 | 実データでの out-of-sample 実証 | AC-16 を満たすデータで完走し、coverage・仮定・改善／悪化を報告 |

ソフトウェアの P0 完成は H3。ヒストリカルでの有効性検証完了は H4 とし、データ未入手なら両者を分けて報告する。

P1 は商品状態の拡張、Asian・離散 Barrier、固定現金配当、詳細 attribution、複数独立市場シナリオ。P2 は LSV 等の別 risk method、連続 Barrier、早期行使、複数原資産、先物・証拠金等とする。実際の初期対象が指数やバリアなら、必要項目を P0 へ繰り上げて再見積もりする。

Barrier 拡張では過去の hit 状態を保持し、再評価時に過去経路を再抽選しない。連続 Barrier の hit は日次終値だけでは確定できないため、観測データ要件または明示した橋渡し近似を別途定める。smoothing を Greeks に使う場合も、実契約の settlement と混同しない。

### 2026-10-04: P0数値受入の具体化

[一般スマイル受入v0.3](validation/vega-kt-smile-acceptance-v0.3.md)は、AC-07の
満期Europeanを静的vanilla複製で検証する。quote別価格差分は式(9)の射影を検査し、
別途SSVI/eSSVI全体の再構築と共通乱数価格差分を検査する。独立quoteの変更を
SSVIパラメータの変更と同一視しない。AC-13の格子比較では市場ショックと基準IV補間を
ともに固定する。旧v0.1の6失敗は書き換えず、合格した同一ショック比較へ紐づけて
supersededと記録する。P1/P2の経路依存Gamma回復やH4の実市場有効性は対象外である。
